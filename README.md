# rootkit-scan：CentOS 7.6–7.9 核心模組 rootkit 黑箱掃描器

> [!WARNING]
> 只在自己擁有、或已取得書面授權的機器上使用。掃描時要用 root 權限讀取大量系統資訊，未經授權對別人的機器使用可能違法。

rootkit-scan 在一台 CentOS 7 伺服器上，找出被核心模組型 rootkit 藏起來的行程、核心模組、網路連線與檔案。

rootkit 是入侵者裝在機器上的惡意程式，作用是讓自己的行程、連線、檔案在一般工具（`ps`、`ls`、`ss`）裡看不見。核心模組型（LKM）的做法是把自己載入作業系統核心，直接改掉核心回答問題的方式，所以連系統內建指令都會被騙。

掃描器不信任任何單一工具的回答。同一件事用多種彼此獨立的方法去問系統，例如先數「有幾條連線」，再逐一列出「每一條連線」。正常的機器各種答案一致；數字是 10、列出來只有 8 條，就是有 2 條被藏起來。這個做法不需要知道 rootkit 用什麼手法，所以稱為黑箱觀測。

## 適用範圍

- 只支援 CentOS 7.6 至 7.9，x86_64，核心 3.10.0-957 起。
- 核心比 957 舊的機器（CentOS 7.5 以前），掃描器會自己停下，並印出一段說明：指出這台機器的核心版本比支援範圍舊、支援範圍是 CentOS 7.6 至 7.9（核心 3.10.0-957 起），並表明沒有執行掃描。
- 其他系統（CentOS 8、Ubuntu、RHEL 7 等）不在支援範圍。程式只比對「核心是否比 957 舊」，不是 CentOS 的系統不會被擋，照樣會往下掃，但掃描結果不可信。
- 程式只能在 Linux 上編譯與執行。只有解密工具可以在 Windows 上使用。
- 掃描結果是線索，不是保證。報告寫「沒有發現」，代表這些問法都沒有看出不一致；能同時騙過每一種問法的 rootkit 看不出來。
- rootkit 可能干擾掃描，例如拖慢系統、擋掉掃描器的某些讀取。

## 專案狀態

版本 0.1.0，早期版本，測試範圍有限。報告格式與選項日後可能改變。

## 快速開始

以下流程在一台 Linux 開發機上編譯，把掃描器送到 CentOS 7.6–7.9 的目標主機，再把加密報告帶回開發機解開。

取得原始碼：用 `git clone` 下載這個倉庫，或下載 ZIP 解壓縮，然後進入原始碼資料夾。Rust 用 rustup 安裝（https://rustup.rs），最低版本 1.85，需要網路（第一次編譯要下載相依套件）。第 3 步的 `rustup target add` 需要 rustup；發行版套件裝的 Rust 通常沒有 rustup。

1. 編譯解密工具：

   ```
   cargo build --release --bin rootkit-scan-decrypt
   ```

2. 在開發機上產生一對金鑰，並把公鑰存進變數：

   ```
   PUBKEY=$(target/release/rootkit-scan-decrypt --genkey --out ~/rootkit-scan.key | grep -o 'rkscan-pub-v1:[0-9a-f]\{64\}')
   echo "$PUBKEY"
   ```

   會印出一行公鑰，格式是 `rkscan-pub-v1:` 後面接 64 個十六進位字元。私鑰寫進家目錄的 `rootkit-scan.key`，權限 0600。私鑰不要放在原始碼資料夾裡，免得跟著資料夾被複製、打包或同步到雲端。`--genkey` 不會覆蓋既有的私鑰檔，檔案已存在時會失敗，換個檔名即可；失敗時 `$PUBKEY` 是空的，`echo` 那一行就是用來檢查這個。

3. 安裝靜態編譯用的目標，並把公鑰編進掃描器：

   ```
   rustup target add x86_64-unknown-linux-musl
   RUSTFLAGS="--remap-path-prefix=$HOME=/home/builder --remap-path-prefix=${CARGO_HOME:-$HOME/.cargo}=/cargo --remap-path-prefix=$PWD=/src" ROOTKIT_SCAN_PUBKEY="$PUBKEY" cargo build --release --target x86_64-unknown-linux-musl
   ```

   第 2、3 步要在同一個終端機視窗做，變數離開這個視窗就沒了。`echo "$PUBKEY"` 沒印出一行公鑰，就不要往下編。要在原始碼資料夾裡執行這行指令（`$PWD` 要是原始碼資料夾）。

   `RUSTFLAGS` 那一串的作用：Rust 會把相依套件原始檔的絕對路徑（例如 `/home/使用者名稱/.cargo/registry/…`）留在程式檔的字串裡，這支程式又要複製到別人的主機上，所以編譯時把這些路徑改寫掉，程式檔就不會帶著你的使用者名稱。三條規則的順序不能換，`$HOME` 那條要放最前面。改變 `RUSTFLAGS` 會讓全部程式碼重編。編完可以檢查（需要 binutils 提供的 `strings`），應該印出 0：

   ```
   strings -a target/x86_64-unknown-linux-musl/release/rootkit-scan | grep -c "/home/$USER"
   ```

   編譯時不檢查公鑰格式，填錯或空白也編得出來；這樣的掃描器執行時一開始就停下，不掃描、不寫檔。換公鑰重編時，cargo 會自動重編，不需要先 `cargo clean`。

   編出的 `target/x86_64-unknown-linux-musl/release/rootkit-scan` 就是跑完會刪掉自己的那一支，不要在開發機上執行它。

4. 用 scp、隨身碟等任何方式，把這支 `rootkit-scan` 複製到目標主機上能執行程式的資料夾，例如 root 的家目錄（以 `noexec` 掛載的位置，例如部分系統的 `/tmp`，不能執行）。用 root 執行；不是用 root 登入的話，用 `sudo ./rootkit-scan`：

   ```
   chmod +x rootkit-scan
   ./rootkit-scan
   ```

   掃描期間螢幕沒有輸出，通常約 10 秒（見〈使用方法〉）。已確認有被藏的行程、卻沒看到被藏的連線時，最多再巡邏 150 秒，期間不要中斷。結束時螢幕只印「掃描完成。」，執行檔所在資料夾只剩一個 `report-主機名稱-日期時間.enc`，`rootkit-scan` 已被刪除。

5. 把 `.enc` 檔帶回開發機，解密。`report-主機名稱-日期時間.enc` 要換成實際的檔名，格式例如 `report-web01-20260101-120000.enc`：

   ```
   target/release/rootkit-scan-decrypt --decrypt report-主機名稱-日期時間.enc --key ~/rootkit-scan.key --out 報告.txt
   ```

   不加 `--out` 時，報告直接印在螢幕上。

> [!WARNING]
> 編入公鑰的掃描器跑完會把自己的執行檔刪掉，要再掃一次得重新複製。不管目標主機是不是 CentOS，編入公鑰的版本跑完都會刪掉自己：程式只檢查核心是否比 957 舊，其他系統不會被擋。不要在開發機上執行它：它會掃描開發機，並刪掉開發機上的這個檔案。私鑰只留在自己的電腦上，不要放到被掃描的主機，也不要上傳到 GitHub；私鑰遺失就解不開舊報告，外洩則任何人都能讀報告。

## 編譯

### 需求

- Rust 與 cargo，最低版本 1.85（`Cargo.toml` 的 `rust-version`）。
- 唯一的外部相依是 `crypto_box`（報告加密用），版本鎖在 `Cargo.lock`。第一次編譯要連網下載它與它的相依套件。

### 一般編譯

```
cargo build --release
```

產物在 `target/release/rootkit-scan` 與 `target/release/rootkit-scan-decrypt`。一個指令會同時編出兩支。

### 靜態單一執行檔

被檢查的機器可能已被入侵，上面的函式庫不一定可信。靜態版把所有需要的程式碼編進同一個檔案，複製過去就能執行，不依賴目標主機上的任何軟體。做法是改用 musl（一套小型 C 函式庫）當編譯目標：

```
rustup target add x86_64-unknown-linux-musl
cargo build --release --target x86_64-unknown-linux-musl
```

產物在 `target/x86_64-unknown-linux-musl/release/rootkit-scan`。不需要另外安裝 `musl-gcc`。

編給別人的主機用時要加路徑改寫，做法見〈快速開始〉第 3 步。

### 解密工具單獨編譯

```
cargo build --release --bin rootkit-scan-decrypt
```

產物在 `target/release/rootkit-scan-decrypt`。它只含加密相關程式碼（`src/bin/rootkit-scan-decrypt.rs`）。

### Windows 版解密工具

解密工具可以在 Linux 上交叉編譯成 Windows 的 `.exe`，在 Windows 上解開報告。掃描器本體只能在 Linux 上編譯與執行。

1. 需要 mingw-w64，它提供 `x86_64-w64-mingw32-gcc`。Debian／Ubuntu 可用：

   ```
   sudo apt install gcc-mingw-w64-x86-64
   ```

2. 加入 Windows 編譯目標並編譯：

   ```
   rustup target add x86_64-pc-windows-gnu
   cargo build --release --target x86_64-pc-windows-gnu --bin rootkit-scan-decrypt
   ```

3. 產物是 `target/x86_64-pc-windows-gnu/release/rootkit-scan-decrypt.exe`。把它複製到 Windows 電腦，同時放好私鑰檔（從開發機複製 `~/rootkit-scan.key` 過去）與從目標主機取回的 `.enc` 檔。

4. 在 Windows 的命令提示字元，切到放這三個檔案的資料夾：

   ```
   rootkit-scan-decrypt.exe --decrypt 報告.enc --key rootkit-scan.key --out 報告.txt
   ```

   `rootkit-scan.key` 是把私鑰檔複製到 Windows 資料夾後的檔名，`報告.enc` 換成實際取回的檔名。報告寫進 `報告.txt`；不加 `--out` 則印在視窗上。`--decrypt`、`--key`、`--out` 的行為與 Linux 版相同。

### 跑測試

```
cargo test
cargo clippy --all-targets -- -D warnings
```

兩者都應該通過。用一般帳號執行即可，不需要 root。

## 使用方法

掃描要用 root。不是 root 時，程式什麼都不讀、不寫，只在標準錯誤印一句「請以root權限執行」就結束。`--genkey`、`--decrypt`、`--replay`、`--version`、`--help` 不需要 root。

### 不加選項：掃描這台機器

```
./rootkit-scan
```

- 掃描時間通常約 10 秒，磁碟上的檔案越多越久。已確認有被藏的行程、卻沒看到被藏的連線時，會再巡邏最多 150 秒等它出現（見 `--watch`），這段時間螢幕沒有輸出。
- 沒有編入公鑰的版本，報告存成執行檔所在資料夾裡的 `report-主機名稱-日期時間.txt`，權限 0600。日期時間用 UTC+8。同名檔案已存在時不覆蓋，改叫 `-2`、`-3`。
- 螢幕只印「掃描完成。」，不印結論、不印報告位置。
- 程式不用結束碼回報結果：不論有沒有發現，結束碼都是 0，要看報告。
- 報告開頭是結果（找到幾個被藏的東西）與清單，之後是每一項的說明，最後附掃描器讀到的原始資料全文（稱為錄製檔），以及掃描器本身的 SHA-256 指紋，可以拿來核對跑的是不是自己編的那一支。

### 所有選項

| 選項 | 作用 |
|---|---|
| `--record 檔案` | 把這次讀到的原始資料另存成一個檔案（內容與報告最後附的錄製檔相同）。無金鑰版寫出的檔案權限為 0644 |
| `--replay 檔案` | 不碰系統，讀錄好的檔案（錄製檔，或最後附有錄製檔的報告），重做判斷與報告，報告印在螢幕上。不需要 root。加密的 `.enc` 要先解密才能重播，直接重播 `.enc` 會得到「stream did not contain valid UTF-8」之類的錯誤 |
| `--watch 秒數` | 已確認有被藏行程、卻沒看到被藏連線時，最多再巡邏幾秒（預設 150；0 表示不巡邏；上限 3600） |
| `--samples N` | 行程取樣份數（預設 3，至少 2） |
| `--gap-ms 毫秒` | 兩份取樣之間的間隔（預設 300） |
| `--content-root 資料夾` | 追加一個要比對檔案內容的資料夾，可重複使用（預設已包含 `/etc`、`/root` 等） |
| `--genkey` | 產生一對新金鑰：公鑰印在螢幕上，私鑰寫到檔案（見 `--out`） |
| `--decrypt 檔案` | 解開加密的報告，要搭配 `--key` |
| `--key 檔案` | 解密時指定私鑰檔 |
| `--out 檔案` | `--genkey` 時是私鑰輸出路徑（預設 `rootkit-scan-private.key`，權限 0600）；`--decrypt` 時是解出報告的輸出路徑（權限依 umask）。指向既有檔案時，`--decrypt` 直接覆蓋；`--genkey` 不會覆蓋，已存在時失敗 |
| `--version` | 顯示版本 |
| `--help` | 顯示完整說明 |

重播不需要 root：在目標主機上掃一次，把報告檔或 `--record` 存的錄製檔取回自己的電腦，用一般帳號 `./rootkit-scan --replay 檔案` 就能重做出一份完全相同的報告。

### 它會動到什麼

平常只讀取，不改系統。兩個例外：

1. 逐埠試占用：掃描器建立自己的網路連接點，試著占用每一個埠，立刻關掉，用來找出被藏的連線。不影響其他程式。
2. 暫時查詢行程：只在已確定有被藏的網路連線、又查不到對方位址時才做。掃描器把握著那條連線的行程暫停約 1 到 3 毫秒，問它連線兩端是誰，然後還原。乾淨的機器不會走到這一步。

另外，它會以唯讀方式直接讀磁碟的區塊裝置（例如 `/dev/sda`），不經過檔案系統。它建立的檔案只有報告，以及用 `--record` 指定的檔案。

## 加密版（編入公鑰）

掃描報告存在被檢查的那台機器上，而那台機器可能已被入侵：報告若是明文，拿到 root 的入侵者讀得到「他被抓到了」。加密版在報告寫進硬碟之前就用公鑰加密，只有私鑰能解開。報告用公鑰加密（libsodium 相容的密封盒，由 `crypto_box` 套件提供）：公鑰只能上鎖、不能解鎖，所以把公鑰編進掃描器沒有風險。

步驟見上面的「快速開始」。私鑰不對或檔案被動過時，解密不會給出部分正確的結果，印「解不開：私鑰不對，或檔案被動過、損毀」；檔案開頭的識別碼不符時，印「這不是本掃描器的加密報告（開頭識別碼不符）」。兩種情況的結束碼都是 1，不輸出任何內容，`--out` 不建檔。

編入公鑰的版本在現場掃描時做這些事：

1. 一開始（讀任何資料之前），請系統「這支程式崩潰時，不要把它的記憶體存成檔案」，避免崩潰留下的檔案裡有報告明文。
2. 報告加密後存成 `.enc`，明文不寫進硬碟。`--record` 指定的錄製檔也加密。
3. 存好報告之後，刪掉自己的執行檔。刪不掉時（例如磁碟唯讀）只印一行提醒。
4. 把還留在記憶體裡的報告明文蓋成 0，盡力而為，不保證每一份複本都清得到。
5. 全部做完才在螢幕印「掃描完成。」。被檢查的機器上只剩加密報告。

沒編入公鑰的版本（開發、測試用）不刪自己、不蓋記憶體，報告是明文 `.txt`。

### 擋得住與擋不住的情況

- 掃描進行的十來秒，資料本來就在記憶體裡。正在即時盯著這台機器、或正在讀這支程式記憶體的人，這個版本擋不住。它防的是跑完之後有人事後撿到東西。
- 自刪只是把檔案從資料夾移除，磁碟上原來的位置沒有覆寫，用磁碟鑑識工具可能找回已刪除的執行檔。
- 記憶體交換區（swap）不在處理範圍：如果系統剛好把那段記憶體換出去，那一份明文不會被清除。
- 記憶體清除只清得到結束前還握在手上的報告與錄製檔兩份；排版過程中複製出去又釋放的中間資料沒有處理。
- 已經掌控系統核心的入侵者擋不住。
- 掃描本身會留下痕跡（多出一個執行中的程式、讀很多檔案），而且加密版跑完連程式本身都不在硬碟上。這台機器之後如果要做鑑識，要先告訴鑑識人員跑過它。

## 分享報告前

報告含主機名稱、網路位址、行程與檔案路徑，最後還附掃描器讀到的原始資料（含系統紀錄片段）。貼到 Issue 或任何公開的地方之前，先檢查並遮蔽敏感內容。

## 看到結果之後

以下是一般性的建議，不是本工具提供的功能，也不是保證。

- 掃描器的結果是線索，不是定論。
- 找到被藏的東西後，不要相信那台主機上任何指令的輸出，rootkit 可以改變指令的回答。
- 把主機從網路隔離，先不要重開機：記憶體裡可能有證據，rootkit 也可能在開機時重新載入。
- 保留加密報告與錄製檔。
- 交給負責資安事件處理的人。
- 核心層級的入侵，一般建議用乾淨的媒體重新安裝，並更換該主機上用過的所有憑證。

## 專案結構

程式分三層，層與層之間只傳遞純資料，所以判斷與排版可以離開被檢查的機器單獨測試：

1. 讀取層（collect）：向系統要資料，不下判斷。
2. 判斷層（judge）：只做計算，不碰系統。比對讀取層給的資料，決定哪些東西被藏。
3. 報告層（report）：把判斷結果排版成給人看的文字。

掃描時可以把讀到的原始資料存成文字檔（錄製檔），之後在自己的電腦上重做判斷與報告，不必再碰那台機器。

`src/` 裡各檔案：

| 檔案 | 用途 |
|---|---|
| `main.rs` | 進入點：解析指令列選項、安排掃描順序、存報告 |
| `model.rs` | 三層之間傳遞的資料格式 |
| `collect.rs` | 讀取層主體：讀行程、核心模組、系統紀錄等 |
| `collect_conn.rs` | 讀取層：網路連線，包含逐埠試占用與暫時查詢行程 |
| `collect_addr.rs` | 讀取層：這台機器自己的網路位址（報告抬頭用） |
| `collect_origin.rs` | 讀取層：被藏行程是怎麼被啟動的（登入身分、服務單元等） |
| `collect_disk.rs` | 讀取層：直接讀磁碟，和檔案系統列出的名單對照，找被藏的檔案 |
| `collect_content.rs` | 讀取層：同一個檔案用兩種方式讀，比對內容是否一致 |
| `collect_exe.rs` | 讀取層：檢查每個行程的程式檔 |
| `collect_deleted.rs` | 讀取層：程式檔已被刪除、卻還在執行的行程 |
| `rawfs.rs`、`rawfs/xfs.rs` | 唯讀的 ext4 與 XFS 解析器，直接讀磁碟上的原始資料 |
| `mounts.rs` | 判斷某個路徑實際放在哪顆磁碟裝置上 |
| `judge.rs` | 判斷層：全部的比對與判定規則 |
| `report.rs`、`report/plain.rs`、`report/plain/deleted.rs` | 報告層：報告的排版與文字 |
| `recording.rs` | 把一次掃描的原始資料存成文字檔，或讀回來重播 |
| `crypto.rs` | 報告加密與解密 |
| `sha256.rs` | 自己實作的 SHA-256（不依賴被檢查機器上的程式） |
| `support.rs` | 檢查核心版本是否在支援範圍內、組報告檔名 |
| `timeutil.rs` | 時間換算 |
| `rawfs_fixture.rs` | 只給測試用：還原測試用的磁碟映像 |
| `bin/rootkit-scan-decrypt.rs` | 獨立的小工具：產金鑰與解密報告，可在 Windows 上使用 |
| `testdata/` | 測試用的磁碟映像（人工產生的小型檔案系統） |
